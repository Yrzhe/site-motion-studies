# Answer Scaffold

一次移动端 AI 生成的完整过程，做成一段 36 秒的可拖动动效：

点开一张卡 → 卡片长成回答 → 收成上下文条 → 起键盘提问 → 发送 → **画一个取景框**
→ 进度爬完，结果在框里显影 → 分叉出两个子任务、**错开**落地 → 点开其中一个看详情
→ 路线图 → 退回主页，整段会话塌成一行历史条。

参考 [@glebich 的 Gen UI thinking](https://x.com/glebich/status/2085585475016819136)
逐帧还原编排与时刻，界面元素全部从零实现，照片用 AI 生成。

## 打开

```bash
open demo/index.html          # 单文件，无运行时依赖，双击即可
```

改动源码后重新构建：

```bash
npm install
npm run dev                   # 本地开发
npm run build                 # 产出 demo/index.html
```

## 它想解决什么

AI 产品的「等待」几乎都长一个样：一个转圈，或者一条匀速的进度条。
两者说的都是同一句话 —— **「你等着」**。它们不说要等多久，不说会得到什么，
更不说系统此刻在干什么。等待因此是一段被浪费的时间。

这件作品的答案是一条贯穿全片的语法：

> **先把要出现的东西占住位置，再往里填。**

它出现了四次，每次换一个规模：卡片展开、取景框、两个空槽、瓦片长满全屏。
因为这条语法一直在，全片没有任何东西是凭空出现的 —— 每一屏都是上一屏的某一块长成的。

## 九个机制

### 1. 临界阻尼阶跃 —— 全片唯一一条曲线

位移、尺寸、透明度、展开度、进度，全部走同一个函数。单调、无过冲：

```js
const OMEGA = 5.4;
const cdRaw = (p) => 1 - (1 + OMEGA * p) * Math.exp(-OMEGA * p);
const CD_NORM = cdRaw(1);
const cd = (t) => cdRaw(Math.min(1, Math.max(0, t))) / CD_NORM;
```

**不变量**：不要换成带回弹的 spring。全片有大量卡片在长大、收小、让位，
任何一次过冲都会读成「弹了一下」，而这件东西的口气是「算好了，放上去」。

### 2. 一切都是 f(T) 的纯函数

没有一条 CSS 动画、没有一个 transition、没有一处 setTimeout。
rAF 只推一个时间标量 `T`，每个组件从 `T` 算出自己这一帧的样式。

**收益**：拖时间轴到任意一刻都能定格，且定格出来的画面**一定是合法的**。
这也是唯一能逐帧和参考视频对比的做法 —— 否则你永远不知道自己在比哪一帧。

**不变量**：任何需要 `getPointAtLength` / `getBoundingClientRect` 的方案都要退回去用闭式解。
比如分叉曲线上那两个小亮点，用的是三次贝塞尔 `t=0.5` 的闭式解 `(P0+3P1+3P2+P3)/8`。

### 3. 取景框 —— 把等待画成一个形状

结果卡出现之前，屏幕上先立起一个**和它一模一样大**的框：

```
FRAME = { x: 88, y: 280, w: 214, h: 321, r: 26 }
```

框不是画上去的，是从一层 53.5px 的「+」点阵里**挑**出来的：两横两竖四条参考线正好
压在点阵的行列上，四个交点是点阵原本的「+」被换成实心亮点，最后补四个圆角。

顺序有意义，反过来就散了：**点阵 → 横线左右展开 → 竖线上下展开 → 交点亮起 → 补圆角**。
前四步说「这块地方被占住了」，最后一步说「它会是一张卡片」。

**不变量**：框和结果必须严丝合缝。差一点点，卡片落位时就会有一次微小的跳，
前面那套「先占位」当场露馅。也因为严丝合缝，卡片落位时**不需要任何位移**。

### 4. 进度曲线：先磨后跳

```
0% → 1% → 4% → 8% → 11%     用了 1.2 秒
11% → 67% → 92% → 100%      用了 1.25 秒
```

线性进度条读作「这个数字是编的」；先磨后跳读作「它真的在算，而且刚才卡在某一步」。

**不变量**：不要平滑这条曲线。它的信息量全在那个拐点上。

### 5. 并行只能靠时间差被看见

两个子任务先落两个空槽（标 NATURE / NIGHTLIFE），右边先填上，**1.8 秒后**左边才填，
等待的那个中间转着一段圆弧。

两个同时落地就只是「出了两张图」；一前一后、后到的还在转，才读作
「两个子任务各跑各的，谁先算完谁先回来」。**并行是一个时间概念，布局说不出来。**

这也给出了压时长的判据：原片这一段有 5 秒纯等待，压掉了大半，
但**错开那 1.8 秒一秒没动** —— 压「什么都没发生」的时间，留「差异本身就是信息」的时间。

### 6. 空槽不能靠涂白来被看见

参考里空槽只比背景亮 **8 个灰阶**（223,224,232 对 214,212,219）。
它能被一眼认出是「一个位子」，靠的是外面那圈很宽的光晕和一道极淡的内描边：

```css
background: rgba(255,255,255,0.22);
box-shadow: 0 0 34px 12px rgba(255,255,255,0.42),
            inset 0 0 0 1px rgba(255,255,255,0.36);
```

**涂白就变成「一张空白卡片」了** —— 位子是「这里将会有东西」，
白卡是「这里有一张没内容的卡」，语义完全不同。

### 7. 照片是长出来的，不是淡入的

所有照片（结果卡、两块瓦片、详情页）都走同一条：
**透明度跟着容器一起来，只有去焦和饱和度单独收敛**。

```js
opacity:   clamp01(g * 1.3)                       // 跟容器同步
transform: `scale(${lerp(1.1, 1, ph)})`
filter:    `blur(${lerp(11,0,ph)}px) saturate(${lerp(0.25,1,ph)})`
```

淡入读作「图早就在，只是刚显示」；去焦收敛读作「刚算出来」。
反过来（让照片晚一步淡入）会先亮出一块灰板，读作**「图挂了」**。

### 8. 共享元素放大时，文字层要脱离动画坐标系

瓦片长满全屏那一下，文字**不能**放在正在放大的那个盒子里：
`left: 28` 在一个 260px 宽的中间态盒子里和在 390px 的终态里落点完全不同，
中途标题会飘到屏幕中间。文字层要反向抵消外层位移：

```jsx
<div style={{ width: 390, height: 844, transform: `translate(${-x}px, ${-y}px)` }}>
```

**判据**：动画中途的每一帧都得是一个合法的界面，不能只有首尾两帧对得上。

### 9. 深色是话题切换的标点，不是风格

全片只有详情页和路线图是深色，连状态栏都跟着反色。

前面五段都在浅色里谈「这东西是怎么算出来的」—— 取景框、进度、分叉、错开，
主语是系统。翻深之后不谈过程，只给内容，主语变成了那个地方。

**一个视觉手段只有在别处不用的时候才有语义。** 如果全片都深色，这一下就白翻了。

## 一条被反复检验的工作方法

这件东西是照着一段 49 秒的参考视频逐帧建的。过程中有四处**结构性**错误
（不是参数偏差，是把东西建错了），全部来自同一个动作：**从缩略图读参考**。

| 我建的 | 实际是 |
|---|---|
| 壁纸有一团暖桃色 | 主页是虹彩的、回答态是冷调的、生成后压一层暖紫 —— **三张**，不是一张 |
| 点阵盘是灰点 | 是**白**点（底色 213、点心 226–239，点比底亮） |
| 连接件是「先线后头」 | 是「白圆头骑在卡底、线从它往下垂」 |
| 触点是一颗从右上走到卡底的圆点 | 是一次**原地**的点按涟漪：盘 → 只剩一圈 → 圈扩大淡出 |

最后一条尤其值得记：我不但把它建错了，还给它编了个说得通的理由
（「它停下的位置就是后来那个连接点的位置」）。**能自圆其说不等于对。**

对应的规矩：

1. **建任何一段之前，先把参考裁到原始分辨率、放大 ≥3 倍。** 缩略图只用来定位时刻。
2. **取样点决定结论。** 「全片没有暖色」是拿三个回答态时刻取样得出的 ——
   换成主页的时刻，结论就反了。
3. **把同一个构件在不同段落里并排对。** 单看每一段都「差不多」，
   并排才看出两段错的是同一个量（点阵盘的盘心一直放低了 75px）。

## 性能：先量帧，再调曲线

接到「动效不顺滑」的第一反应不该是调缓动。用 rAF 间隔当尺子逐层剥离：

| 状态 | p50 | >20ms 的帧 |
|---|---|---|
| 原样 | 16.6ms | 50/240 |
| 去掉全部 `backdrop-filter` | 16.6ms | 几乎没变 |
| **再去掉全部 `filter: blur()`** | **8.3ms** | 0 |

贵的不是卡片上的毛玻璃，是壁纸那 4 个 `filter: blur(34px)` 的漂移色团 ——
而它们的位移是 52 秒走 3%，**看不见**。改成纯 radial-gradient 的静态层之后，
主循环 16.6ms/帧 → 8.3ms/帧。

同类的账还有三笔，都是「每帧重建从不变化的东西」：五百个点阵 `<circle>`、
四十个键、行星球体。全部提到模块层做成常量元素之后，React 每帧比到同一个引用
就整棵子树跳过。

还有一个真 bug：光标曾被写成 render 函数体内定义的组件 ——
**在 render 里定义组件 = 每帧换一个组件类型，React 会把节点卸载重挂一次**，
看上去就是「在闪」，很容易误判成缓动没调好。
